# Antigravity CLI (`agy`) TUI Binary Patch Specification

The file name is historical: the patch began as a context-window unlock and now also restyles chain-of-thought (CoT), palette, and user-prompt rendering.

Target binaries (`darwin/arm64`):
- **Location**: `~/.local/bin/agy`. `~/.gemini/bin/agy` is the hub wrapper script and is never patched.
- **Backup**: only the current version's clean copy is kept (`~/.local/bin/agy.v<ver>.orig`); `--apply` always patches from it.
- **Verified Versions**:
  - `agy v1.5.0` (`201,432,752` bytes, original `SHA-256: e61679b8ba54abae9a56534208e21f65e1dede6e4eb0144dbd64535f42d07724`)

## 1. Two Ways to Control the Context Window

`agy` ships with complete backend and TUI support for controlling the context window on **Gemini 4 Argon** (`model.MaxTokens = 1,000,000`), including a built-in interactive Context selector inside `/model` and a statusline badge.

| Capability | Method 1: Binary Patch (`patch_agy.py --apply`) | Method 2: Env Override (`AGY_CLI_AUTO_COMPACT_OVERRIDE`) |
| :--- | :--- | :--- |
| **Interactive `/model` TUI (`Tab` key)** | **Enabled** — cycles `Default` $\rightarrow$ `256K` $\rightarrow$ `512K (1.3x)` $\rightarrow$ `900K (1.8x)` | **Read-only** — displays gauge locked to override value |
| **`settings.json` persistence** | **Enabled** — reads & saves `"contextWindow": "512K"` | Bypassed while env var is set (`env` takes precedence) |
| **Custom non-preset token counts** | Presets only (`256K`, `512K`, `900K`) | Any `uint32` token count (e.g. `512000`, `640000`) or `1%`–`100%` |
| **Binary modification** | 41 sites (`968` bytes) + ad-hoc `codesign` | None |

> **Important**: `AGY_CLI_AUTO_COMPACT_OVERRIDE` is evaluated **before** the preset selector. If `AGY_CLI_AUTO_COMPACT_OVERRIDE` is set in your shell, `/model` will lock the Context selector to that override value (`overridden by AGY_CLI_AUTO_COMPACT_OVERRIDE=...`). To use the interactive `Tab` TUI in `/model`, unset `AGY_CLI_AUTO_COMPACT_OVERRIDE` and apply the binary patch.

## 2. End-to-End Architecture in `agy`

### 2.1 Preset Definitions & Token Conversion (`google3/third_party/jetski/cli/backend`)
- **`backend.ContextWindowSelectable`**: Global slice containing `["Gemini 4 Argon"]`. `v1.5.5` added Gemini 4 Carbon (same `1,048,576`-token window) without adding it here, and Gemini 4 Hydrogen (Sites #55a–#55p) shares the window; Sites #1a–#2b admit every `Gemini 4 ` name.
- **`backend.ParsePresetContextWindow`** (`v1.5.0: 0x102851cd0` / `v1.5.1: 0x102875970`): Case-insensitively (`strings.EqualFold`) validates the three presets:
  - `"256K"` (`1x` quota)
  - `"512K"` (`"1.3x"` quota multiplier)
  - `"900K"` (`"1.8x"` quota multiplier)
- **`backend.ContextWindow.MaxTokenLimit`** (`v1.5.0: 0x102851da0` / `v1.5.1: 0x102875a40`):
  - If the `ContextWindow` string ends with `'K'` (`0x4b`), strips `'K'`, parses base-10 `uint32`, and multiplies by `1000` (`"512K"` $\rightarrow$ `512000`).
  - Otherwise, parses the raw base-10 `uint32` directly (`"512000"` $\rightarrow$ `512000`).

### 2.2 Protobuf Wire Path (`ServerBackend.buildCascadeConfigInternal`)
`buildCascadeConfigInternal` (`v1.5.0: 0x102860d30` / `v1.5.1: 0x1028849d0`) resolves `(*ServerBackend).ContextWindow().MaxTokenLimit()` and populates `CascadeConfig.CheckpointConfig.MaxTokens`:
```arm64
bl     (*ServerBackend).ContextWindow
bl     ContextWindow.MaxTokenLimit
cbnz   w0, +0xc                          ; if limit != 0
...
bl     runtime.newobject                 ; type:*cortex_go_proto.CheckpointConfig
ldr    w1, [sp, #0x50]                   ; w1 = limit (e.g. 512000)
str    w1, [x0, #0xc]                    ; CheckpointConfig.MaxTokens = limit
str    x0, [x1, #0x10]                   ; CascadeConfig.CheckpointConfig = cpCfg
```

### 2.3 The Built-in TUI in `/model` (`google3/third_party/jetski/cli/model`)
The interactive TUI is compiled into `model.SelectorModel`:
- `SelectorModel.Update` (`v1.5.1: 0x102d9f1d0`): Handles `KeyTab`, calling `(*SelectorModel).cycleWindow` (`v1.5.1: 0x102da45a0`) to cycle `""` (`Default`) $\rightarrow$ `"256K"` $\rightarrow$ `"512K"` $\rightarrow$ `"900K"`.
- `renderWindowOptions` (`v1.5.1: 0x102da5990`): Renders the horizontal Context option strip (`Default`, `256K`, `512K (1.3x)`, `900K (1.8x)`) and `[Tab]` hint in `/model`.
- `SelectorModel.selectRow.func1` (`v1.5.1: 0x102e54bd0`): Calls `(*Manager).SetContextWindow` (`v1.5.1: 0x102b92740`) on `Enter` to persist `"contextWindow"` into `~/.gemini/antigravity-cli/settings.json` (struct offset `+0x70`) and push it to `ServerBackend.SetContextWindow` (`v1.5.1: 0x1028888d0`).
- `StatusLineModel.modelDisplayWithBadge` (`v1.5.1: 0x102e20710`): Appends the active context window badge (e.g. `Gemini 4 Argon · 512K`) to the TUI statusline.

### 2.4 Why the TUI Is Gated Upstream
Two functions gate the entire feature:
1. **`store.(*Store).ContextWindow`** (`v1.5.0: 0x102b6c390` / `v1.5.1: 0x102b92540`)
2. **`model.SelectorModel.offersContextWindow`** (`v1.5.0: 0x102d76db0` / `v1.5.1: 0x102da3ac0`)

In both functions, after verifying the model is in `backend.ContextWindowSelectable` (`"Gemini 4 Argon"`), the code performs an interface type assertion on `s.features` (`offset +0xb8`, populated with `*experiments.MockFeatureProvider`) against `*types.FeatureFlagReader`. Because the flag check was compiled as a constant `false`, both the hit and miss branches of `runtime.typeAssert` jump directly to the failure path:
- In `(*Store).ContextWindow`, both branches jump to `return ""`, leaving `(*Store).ContextWindowChoice` (`v1.5.0: 0x102b6c330` / `v1.5.1: 0x102b924e0`) with zero callers in the binary.
- In `SelectorModel.offersContextWindow`, both branches jump to the fallback path that only returns `true` if `AGY_CLI_AUTO_COMPACT_OVERRIDE` is non-empty.

## 3. Version-Adaptive Resolution (`patch_agy.py`)

Rather than relying on static file offsets that break when `agy` auto-updates, `patch_agy.py` resolves all 41 code patch sites (`968` bytes) dynamically:
1. **Mach-O `__lrodata_gopcln` Symbol Lookup**: Parses the 64-bit Mach-O section headers (`__text` and `__lrodata_gopcln`) and Go 1.20+ `pclntab` (`magic = 0xFFFFFFF1`) to find the exact `[start_offset, end_offset)` boundaries of the 26 target functions.
2. **Invariant Pre-Anchors**: Within each bounded function, locates the exact patch offset using the (typically 4–16 byte) instruction sequence immediately preceding the patch site (which remains unmodified whether the binary is unpatched or already patched, and is verified to be unique inside the function).
3. **Dynamic ARM64 `bl` Encoding**: Automatically computes the 26-bit signed word displacement (`0x94000000 | (((target - pc) >> 2) & 0x03FFFFFF)`) for all cross-function `bl` calls (Sites #1, #4, and #6).
4. **Versioned Clean Backups**: Detects the binary version via `agy --version` and creates a version-specific clean backup (`agy.v1.5.0.orig`, `agy.v1.5.1.orig`, etc.) before patching.

### Sites #1a–#2b: Admit the Gemini 4 Family (`v1.5.5+`)
Without these sites a Carbon or Hydrogen session splits: Site #3 honors `"contextWindow": "512K"` for any model of at least `1M` tokens, so the statusline and `/context` show `512K`, but `store.(*Store).ContextWindow` returns `""` before reaching Site #1, so `store.(*Manager).syncContextWindow` never hands the preset to Cortex, and `/model` hides the `Tab` selector.

Both functions end their `ContextWindowSelectable` loop the same way, with the name in `x0` and its length in `x1` (`ContextWindow`) or `x2` (`offersContextWindow`):
```diff
  ; whitelist miss
- mov  x0, #-1                       ; Sites #1a / #2a
+ b    <matcher>
  tbnz x0, #63, <miss>               ; hit falls through to <hit>
```
The matcher (Sites #1b / #2b, `v1.5.5`: `0x102d1d270` / `0x102f6eac4`) lives `0x34` past Site #1 / #2, in code those sites leave unreachable:
```asm
cmp  x<len>, #9
b.lo <miss>                          ; shorter than the prefix
adr  x1, <literal>                   ; "Gemini 4 \0", the next 16 bytes
mov  x2, #9                          ; compare the prefix only
bl   runtime.memequal                ; same call the whitelist loop makes
tbz  w0, #0, <miss>
b    <hit>                           ; ContextWindow: 0x102d1d1e4, offersContextWindow: Site #2
```
Upstream's slice still drives the loop, so a model Google adds to it later needs no patch. `<miss>` and `<hit>` are decoded from the `tbnz`, and `runtime.memequal` from `pclntab`. The prefix lives in `CONTEXT_WINDOW_EXTRA_FAMILY`; it must fit the 16-byte literal slot. ### Sites #41–#47: Live Light/Dark Switching (DEC Mode 2031)
The bar color is a fixed 256-color gray, so unlike the ANSI-indexed colors it does not follow a terminal theme switch by itself: `agy` has to learn of the switch. Upstream asks for the background once, at startup (OSC 11), and never enables DEC mode 2031, through which Ghostty and other terminals announce each switch (`CSI ? 997 ; 1 n` dark, `; 2 n` light). No ANSI slot can stand in for the bar: in a dark theme it wants a shade just above the background (Peppermint: slot 0, `#353535`), in a light theme one just below (Modus Operandi Tinted: slot 7), and no slot is both.

bubbletea v2 already does most of the work. ultraviolet decodes the notifications into `uv.DarkColorSchemeEvent` / `uv.LightColorSchemeEvent`, `translateInputEvent` passes events it does not know through unchanged, and the event loop answers its internal `backgroundColorMsg` (what `tea.RequestBackgroundColor` returns) with an OSC 11 query. The sites connect these pieces, all inside bubbletea:
- **Sites #41–#45 (renderer, `28` bytes)**: Lend the mode the focus-reporting lifecycle, which `agy` never uses (`View.ReportFocus` stays false). The two `ansi` strings `ESC[?1004h` / `ESC[?1004l` become `ESC[?2031h` / `ESC[?2031l` (#44, #45; each is referenced only by the renderer's `start`, `close` and `flush`). The `ReportFocus` tests that guard their writes are dropped in `start` (resume, #41) and `close` (exit and suspend, #42), and taken unconditionally on `flush`'s first frame (#43). The mode is on while `agy` runs and off once it exits or suspends, so a theme switch never types `^[[?997;2n` into the shell.
- **Site #46 (`translateInputEvent`, `4` bytes)**: The default case (`return e`) branches to the matcher.
- **Site #47 (matcher, `64` bytes)**: Returns `backgroundColorMsg{}` (`(type, &runtime.zerobase)`, both read from `tea.RequestBackgroundColor`) for either event, and the event unchanged otherwise. It lives in the 120-byte span Site #29 leaves dead in `StickyPrompt`; `assert_unreachable` refuses the span if any other branch in the function reaches it. The two event types are found by name: `abi.Type.Str` is a `nameOff` from `moduledata.types`, which is recovered from the `backgroundColorMsg` descriptor.

From there the existing path runs: the OSC 11 reply becomes a `BackgroundColorMsg`, `RootModel.update.func2` calls `SetTerminalBackground`, and Site #34 stores `237` or `254` and rerenders. Verified in a pseudo-terminal acting as Ghostty: `ESC[?2031h` on the first frame, an OSC 11 query on each notification, the bar's `48;5;237` turning `48;5;254` and back, and `ESC[?2031l` on exit.

## 5. Authoring Pitfalls

### 5.1 Hand-assembled hex (2026-11-08 crash)
Most patched bytes are literal `bytes.fromhex(...)` instruction words. A one-nibble error turns `[sp, #imm]` into `[xN, #imm]`, which dereferences whatever the caller left in `xN`. This shipped twice in the same change:

| Site | Wrong | Intended | Hex |
| :--- | :--- | :--- | :--- |
| #24 | `str xzr, [x7, #0x378]` | `str xzr, [sp, #0x378]` | `ffbc01f9` → `ffbf01f9` |
| #28 | `ldr x24, [x15, #0x5b8]` | `ldr x24, [sp, #0x5b8]` | `f8dd42f9` → `f8df42f9` |

When `xN` held unmapped garbage, the CLI crashed with `SIGSEGV` in `renderUserPrompt` (fault address `0x75745f65636972ee`, which is `x7 = "voice_tu"` + `0x378`). When it held a valid pointer, the write silently zeroed 8 bytes of live heap. Both were fixed in `patch_agy.py`.

**Before applying any new or edited site, disassemble it and read every memory operand.** A base register must be `sp`/`x27`/`x28`/`x29` or set earlier in the same site, or it must be provably live from the surrounding code:
```sh
objdump -d --no-show-raw-insn --start-address=<va> --stop-address=<va+size> ~/.local/bin/agy
```

### 5.2 Hard-coded stack offsets
Patched bytes embed frame offsets (`[sp, #0x378]`, `[sp, #0x5b8]`, ...). A new release can reshape a frame without breaking an anchor that does not include those offsets. After each upgrade, compare the patched function against the new `.orig` before trusting `--status`.

An anchor that spells a frame offset fails the other way, loudly: Site #7d's pre-anchor included `ldr x5, [sp, #0x2d0]`, and `v1.5.8` moved that slot to `#0x2e8`. Anchor on the instructions that do not name the frame (`ldrsw x5, [x5, #8]; cmp w5, #0xe`).

### 5.3 The bar-color byte
Sites #21, #24 and #34 share one mutable byte at `runtime.zerobase − 8` (`v1.5.3: 0x10c62bb78`, `v1.5.5: 0x10c70ae38`, `v1.5.6: 0x10dd98938`). It is safe only because it falls in the alignment gap between the end of `__bss` (`v1.5.3: 0x10c62bb70`, `v1.5.5: 0x10c70ae30`, `v1.5.6: 0x10dd98938`) and the start of `__noptrbss` (`v1.5.3: 0x10c62bb80`, `v1.5.5: 0x10c70ae40`, `v1.5.6: 0x10dd98940`). If a future layout closes that gap, the byte becomes the tail of a GC-scanned `__bss` variable. In `v1.5.6` the gap shrank from 16 bytes to 8 and the byte is the first one past `__bss`, so there is no margin left. Check with `otool -l <binary>` after every upgrade.

### 5.4 Struct fields move between releases (v1.5.6)
`v1.5.6` reordered fields in several structs: `ConversationModel` grew by `0x20`, the store's model by `0x158`, and `Store.settings` moved from `+0x10` to `+0x0`. Anything that spells a field offset broke, in two different ways:

| Where the offset was | Sites | Symptom |
| :--- | :--- | :--- |
| Anchor bytes | #15, #32 | Anchor not found; `--status` stops. Loud and safe. |
| Expected original bytes | #1, #3 (`MODEL_MAX_TOKENS_ORIG_HEAD`) | Clean backup reads as `unknown`; `--apply` refuses. Loud and safe. |
| Patched bytes | #3 (`ldr x6, [x6, #0x10]`) | Anchor still matches and `--status` reads `patched`, but the resolver loads the wrong `Store` field and dereferences it as `settings`: a wrong window limit, or a crash. **Silent.** |

Anchor on the instruction, not the field: mask the offset (`LDR_X_ANY_OFFSET`, `find_unique_words`). When patched code walks a struct, take each offset from a function that upstream keeps walking the same way (Site #3 reads both from `(*Store).ContextWindowChoice`, and refuses to resolve if its shape changes). After an upgrade, a site whose bytes are derived from the binary always reads as clean, so `--status` cannot catch this class: write the patches into a copy of the new release, disassemble every site, and check each non-`sp` memory operand against the code around it.

### 5.5 Calls from patched code (v1.5.6)
The garbage collector and the stack copier read every frame through the stack maps of the PC it stopped at: `pclntab` records, per call site, the frame size and which slots hold pointers. Code placed in a dead span is attributed to the function that owned the span, so a `bl` from there is scanned by a foreign map: a live pointer the map does not list can be freed, and a small integer in a slot it lists as a pointer aborts the stack copy (`invalid pointer found on stack`). Code caves therefore call nothing that can grow the stack or stop for the collector: Site #47's matcher is a leaf, and the Carbon matcher (Sites #1a–#2b) calls only `runtime.memequal`, a nosplit assembly leaf. When new behavior needs calls, rebuild a function whose job is no longer needed and keep each call at a PC where stock called (Site #50d: `Time.Sub` → `time.Since`, `convTstring` → `convT64`). Write only scalars to scalar slots, keep pointer slots holding a pointer or nil, and pass nil in pointer-typed argument registers, since `morestack` spills them into slots that are scanned as pointers.

### 5.6 Distances from a landmark (v1.5.8)
Sites #19–#21 were located at fixed distances from the palette copy loop in `resolveStyles`. `v1.5.8` added code between the loop and the styles they patch, and the three failed in three ways:

| Site | Its original bytes | Symptom on the clean `v1.5.8` |
| :--- | :--- | :--- |
| #19 | computed from the palette slot | Reads `unknown`; `--apply` refuses. Loud and safe. |
| #20 | a fixed copy loop | Reads `unknown`; `--apply` refuses. Loud and safe. |
| #21 | read from the binary at the computed offset | Reads `unpatched` wherever it lands, and would have overwritten 20 bytes of the new code. **Silent**, and stopped only because #19 and #20 failed first. |

Locate a site by what its code does (here, the `add x27, sp, #pal+0x40` that opens `UserPrompt`).

The silent case is closed for every site at once by **stock shapes**. A shape is a site's stock instructions with the operands that move between releases masked out: branch and page targets, `add`/`sub` immediates (`cmp` keeps its own), and load/store offsets. [`site_shapes.json`](../site_shapes.json) holds, per site, the shapes a person has reviewed. `--apply` refuses a clean binary that shows any other, naming the sites, and `--accept-shapes` records them after review. A frame slot or a field that moves leaves the shape unchanged (`v1.5.8` passes on `v1.5.7`'s shapes alone), while different instructions do not (Site #21 at its old distance is refused). A new site has no shape until its author records one, so it cannot be applied unreviewed. Sites outside `__text` (strings, the spinner's frame slice, monitors, prompt templates) have literal or stock-checked originals and are not shaped.

### 5.7 Proving a new release
`--status` proves bytes, not behavior. `probe_agy.py rehearse` does the whole rehearsal on copies and ends in one table: what stock sends, templates and rendered prompt against the previous release, every site group (`keep`, `retired`, `RE-AUTHOR`), stock shapes, the patched copy's state and signature, and the three probes below. `FAIL` and `REVIEW` stop the upgrade; `READ` marks a difference to attribute to upstream or to us. The probes also run alone:
- `sites <old .orig> <new .orig>` lists every site whose patched bytes or surrounding stock code differ from the previous release, addresses aside. Each flagged word should be a frame slot or a field that moved (§5.2, §5.4), never a different instruction.
- `wire` prints the model and `thinkingLevel` each picker ID sends. Run it on the stock release first: a site whose behavior upstream now ships should retire, even though it still resolves (Sites #55a–#55n resolved on `v1.5.8`, and would have replaced 3.6 Flash with a second Hydrogen).
- `tui --against <snapshots of the installed version>` drives a canned turn, `/model` and `/context`, and diffs the screens with their styles.
